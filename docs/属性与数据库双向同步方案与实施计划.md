**一句话**：AV 与 IAL 之间没有自动桥（「反向报告」结论不变），但**两侧的变更都以「携带完整新值的事件」形式广播到本机**，插件可以在事件层做一次精准、定向、可终止的双向翻译。

## 3. 为什么事件驱动双向不会出现「静默覆盖」

「反向报告」§8 指出的最大风险是：

> 面板改属性 → AV 里仍是旧值 → 下次 AV 变更触发镜像 → 旧值反写回属性，静默覆盖用户修改。

**该风险的成因是「全表镜像」这一实现方式**：镜像每次都拿整张表的快照去反写所有单元格，于是「表里尚未更新的旧值」被当成「用户意图」写回。这是「反向报告」方案 A 的固有缺陷，而不是双向同步的固有缺陷。

本方案改为**事件驱动 + 定向翻译**：只在**收到一次变更事件**时，翻译**这一个值**，两侧都遵循「**只写差异**」。于是：

1. **不存在陈旧快照**。我们从不读取「整表现状」去反写，只写「刚刚被 op 明确告知的新值」。面板改了属性 → IAL 变更事件立刻把新值推给 AV；AV 里不会再留着旧值等着反噬。
2. **任何回声在一步内终止**。三条链路都验证过：

| 起点 | 链路 | 是否回声 |
| --- | --- | --- |
| 面板改属性 | IAL 写 → `updateAttrs` op（含自身）→ 写 AV（**HTTP 直连，不产生 AV op**）→ 结束 | 否 |
| 数据库改单元格 | `updateAttrViewCell` op（含自身）→ 写 IAL → `updateAttrs` op（含自身）→ 写 AV（**HTTP 直连，不产生 AV op**）→ 结束 | 一轮后终止 |
| 数据库内新增/删除行 | `insertAttrViewBlock` / `removeAttrViewBlock` op → 只更新本地索引（非绑定行计数）→ 结束 | 否 |

   关键是 **N4 + 「插件 AV 写入不产生 op」**：写 AV 的那一步是「汇」，不是「源」。

3. **多端一致**。所有端从**同一个 op** 推导出**同一个值**，后到的写因「只写差异」变成 no-op，因而收敛（LWW by 到达顺序，见 §8）。

唯一还需要额外防护的是「无谓回写」：AV 单元格 → IAL → 再写回 AV 这一轮，AV 侧的值本来就是源头，回写只会让所有客户端各多刷一次数据库 UI；而当文本单元格带富文本源（`text.rich`）时，回写的 `content` 与旧值不同还会让内核清空 `rich`（`kernel/model/attribute_view.go:8166-8172`），造成真实的格式丢失。所以 §7 引入**回声令牌（echo token）**：由 AV 变更引发的 IAL 写入会登记 `(blockID, attrKey, 值)`，随后到达的对应 `updateAttrs` op 在同键同值时被跳过。

### 4.3 AvIndex：行/列映射缓存

`avID → AvIndex`，惰性构建、事件失效：

```ts
interface AvIndex {
  avID: string
  builtAt: number
  blockKeyID: string | null                    // 主键列
  columns: Map<string, AvColumn>               // keyID → 列
  byAttrKey: Map<string, AvColumn>             // 属性全名 → 列
  rowToBlock: Map<string, string>              // itemID → 绑定块 ID（游离行不在其中）
  blockToRow: Map<string, string>              // 绑定块 ID → itemID
  detachedRowIds: Set<string>                  // 游离行 itemID（用于 UI 标记）
}
```

- **构建**：首个涉及该 avID 的 op 到达时调用 `renderAttributeView(avID)`（一次），解析列与行。`pageSize` 沿用 9999（「反向报告」§8 的性能提示已由「按 avID 惰性 + 缓存 + 失效」化解：一个数据库只在整个会话的首次变更时读一次）。
- **失效**：结构性 op（`addAttrViewCol` / `updateAttrViewCol` / `removeAttrViewCol` / `sortAttrViewCol` / `insertAttrViewBlock` / `removeAttrViewBlock`）后标脏；cell op 引用了未知 `rowID` 或未知 `keyID` 时标脏重取；TTL（5 min）到期。
- **op 直填**：`insertAttrViewBlock` 的 `srcs[]`（含 `itemID` / `id` / `isDetached`）可直接写入映射，省一次 render（N6 保证 `itemID` 可用）；`removeAttrViewBlock` 的 `srcIDs` 直接删。
- **列 → 属性名的映射优先级**：注册表 `keyID → 属性全名` 优先（用户改了列名也不失效）→ 否则回退「列名本身形如 `custom-<suffix>` 就当属性名」→ 都不满足则不参与同步。

### 4.4 保留键黑名单

以下 `custom-` 前缀键由内核维护，**必须排除**，否则会把 AV 绑定状态当成普通属性来回搬运：

## 5. 类型编解码

### 5.1 规则

- **AV → IAL**：只按 **AV 列类型**把单元格值解码为标量并串化（列类型是单元格值的唯一事实来源）。
- **IAL → AV**：先按 Schema 类型把 IAL 字符串**分词/规范化**（如 multi-select 的拆分），再按 **AV 列类型**构造单元格值。
- 两侧都遵循既有序列化约定（`CLAUDE.md`）：multi-select 用 `", "` 连接、date 用 `YYYY-MM-DD`、checkbox 存 `'true'/'false'`、block-ref 存原始块 ID。
- **空值**：IAL 空串 = 删除属性（思源语义）；AV 单元格空值按列类型写空（见下表）。
- **写入是合并语义**：内核把 `valueData` 反序列化进**已存在的值对象**（`kernel/model/attribute_view.go:8140-8156`，文本/主键类型先克隆），未出现的字段保留原值。因此只写 `{ date: { content, isNotEmpty, isNotTime } }` **不会**抹掉日期区间的 `hasEndDate`/`content2`，也不会重置数字列的 `format`。唯一的例外是文本列：当写入的 `content` 与旧值不同时会清空 `text.rich`（富文本源），这是「回声令牌」要防的真实丢损场景（见 §7）。

### 5.2 映射表

| AV 列类型 | AV 单元格值（写） | IAL 字符串 | 备注 |
| --- | --- | --- | --- |
| `text` | `{ text: { content } }` | 原样 | 兜底类型 |
| `number` | `{ number: { content, isNotEmpty } }` | 十进制字符串 | IAL 非数字 → 跳过并告警 |
| `date` | `{ date: { content: ms, isNotEmpty, isNotTime } }` | `YYYY-MM-DD`（AV 侧含时间则 `YYYY-MM-DD HH:mm:ss`） | 时间信息在 IAL 侧同样保留，故往返无损；区间字段由内核合并语义保留（§5.1） |
| `select` | `{ mSelect: [{ content, color: '' }] }` | 单值原样 | 选项不存在时内核自动创建（N7） |
| `mSelect` | `{ mSelect: [{ content, color: '' }, …] }` | `", "` 连接 | 值内含逗号无法往返（既有约定） |
| `checkbox` | `{ checkbox: { checked } }` | `'true'` / `'false'` | 解码时 `'1'` 亦视为勾选（与既有 UI 一致） |
| `url` / `email` / `phone` | `{ url/email/phone: { content } }` | 原样 | |
| `block`（主键列） | `{ block: { id, content }, isDetached: false }` | `custom-avs`（只读，不参与） | 仅用于绑定/改绑，不参与值同步 |
| `mAsset` | `{ mAsset: [{ type, name, content }] }` | 资源路径列表 | **v1 不参与同步**（去重/编码规则复杂），登记但不翻译 |
| `relation` / `rollup` / `template` / `created` / `updated` / `lineNumber` | — | — | **不参与**（前两者是引用/派生；后四者是系统或渲染期字段，N9 同源） |

### 5.3 单元格清空

写空 mSelect 时内核会提前 `return`（`kernel/model/attribute_view.go:8220-8222`），但此时已就地改写了内存中的值对象，随后的 `av.SaveAttributeView` 仍会落盘空值 → 清空可生效。**该路径需在 Phase 2 真机实测**（列入 §11 验证清单）。

## 6. 同步范围与登记

- **注册表**：`plugin.saveData('av-sync.json', { version, entries })`，`entries[avID] = { avID, name, enabled, mapping: { keyID: 属性全名 } }`。
- **自动登记**：`createDatabaseFromSelection()` 建表成功后立即写入一条 `enabled: true` 的记录，并把 `keyIdMap` 直接落进 `mapping`（此时映射是精确的，不依赖列名推断）。
- **手动控制**：数据库统计卡片（`NotebookDbStats.vue`）上提供开/关；未登记的数据库显示「启用同步」按钮。
- **总开关**：设置页新增 `avSyncEnabled`（默认 **true**，但注册表为空时无任何行为）与 `avSyncMode`（`bidirectional` | `av-to-attr` | `attr-to-av`，默认 `bidirectional`）。
- **持久化写入沿用既有防广播约定**：与 `saveSettings` / `saveAllSchemas` 一致，JSON 未变化则跳过 `saveData`，避免凭空制造跨端广播（`CLAUDE.md`「不可改动项」）。
- `onDataChanged()` 中追加 `reloadAvSync()`，`uninstall()` 中追加 `removeData(AV_SYNC_STORAGE_NAME)`。

## 7. 防环、并发与幂等

| 机制 | 作用 | 实现 |
| --- | --- | --- |
| **事件驱动定向翻译** | 不用全表镜像，从根上消除「陈旧快照反写」（§3） | §4.2 |
| **只写差异** | 避免无意义写入与 `updated` 抖动；多端重复处理同一 op 时收敛为 no-op | IAL 侧与 `op.data.new[attrKey]` 比对；AV 侧与索引中最后已知值比对 |
| **回声令牌** | 阻断「AV → IAL → 再写回 AV」这条无谓回写路径（并防住文本列 `rich` 被清空的丢损场景） | `Map<'blockID\u0000attrKey', { value, expiresAt }>`，TTL 2s，写入 IAL 时登记，IAL→AV 前**同键同值**命中即跳过并消费令牌。按值匹配而非仅按键匹配，是为了让用户在窗口期内从面板改成别的值时仍能正常推送 |
| **合并防抖** | 连续输入不逐字触发跨 API 写 | AV→IAL 按 `avID:keyID:rowID` 保留最新值，120ms 冲刷；IAL→AV 按 `blockID:avID:keyID` 同理 |
| **串行化** | 同键写入不乱序 | 复用 `useBlockAttrs` 的 `chainWrite` 思路（按 key 的 Promise 链）；AV 侧按 `avID:keyID:rowID` 串行 |
| **异常隔离** | 同步失败不得影响编辑器 | 所有写回 `try/catch` + `logger` 条件日志；失败不回滚 IAL（源侧已是真相） |
| **熔断** | 防止极端环路耗电 | 单次刷新窗口内写回次数上限（默认 200），超限即停并告警 |

**终止性论证**（写给未来的维护者）：写 AV 的路径是 HTTP 直连 API，内核不产生 `updateAttrViewCell` op（§2 补充事实）；写 IAL 的路径产生的 op 已被回声令牌与差异比对拦住。故图中不存在长度 > 2 的环。

## 8. 冲突与仲裁

**默认 LWW（后到者胜），依据 op 到达顺序**。理由：

- 事件驱动下，每次冲突都是「两个真实发生的用户动作」，按到达顺序取最后一个符合直觉，且天然收敛（不引入额外的时钟假设）。
- 跨端离线场景里，`updated` 时间戳是块级而非键级，用它做仲裁会在「同一块的另一个属性被改」时误判；AV 侧也没有键级时间戳。**故 v1 不引入时间戳仲裁**（「反向报告」§8 的选项 2 需额外写 `custom-av-sync-ts`，收益不足以抵消其引入的新状态）。

**例外规则**：

1. **绑定时属性胜**：`insertAttrViewBlock` 携带非游离 `srcs[]` 时（用户把块拖进数据库 / 插件建表），**不**把（通常为空的）AV 单元格值推给块，而是**反向把块的 IAL 回填进 AV**。依据是 N9：内核不会替用户做这件事，而用户已有的属性值显然应该是真相。
2. **方向开关优先于 LWW**：`avSyncMode` 设为单向时，另一方向只读不写。
3. **不可表达即跳过**：往返不成立的值（如含逗号的 multi-select）只写能表达的一侧，并在调试日志中记录，绝不写入半成品。

- `AvIndex.detachedRowIds` 与 `useNotebookDbStats` 的 `detachedCount` 提供计数；数据库卡片上以徽标显示「N 行未绑定」。

## 10. UI 与 i18n

**数据库统计卡片**（`NotebookDbStats.vue`，`AttrStats.vue` 的 stats 页已挂载）：

```
┌────────────────────────────────────────┐
│ 项目台账                    [同步: 开] │
│ status、priority、owner                │
│ 行: 24    绑定块: 22    ⚠ 未绑定 2 行  │
│ 创建: …   更新: …                      │
│ 已开启双向同步            [立即同步]   │
└────────────────────────────────────────┘
```

- 「立即同步」= 对已启用数据库跑一次**定向全量对账**（遍历索引内绑定行，按列比对后仅写差异），用于兜底（例如开关刚打开、或用户手工在 AV 里批量粘贴过数据）。规则是**只补空**：AV 空则用 IAL 填、IAL 空则用 AV 填，两侧都有值且不同则跳过——一键同步不覆盖任何已有数据。单向模式下只补「允许写入的那一侧」。
- i18n：新增键需 `zh_CN.json` / `en_US.json` **同步维护**（当前各 194 个键）。本次新增 `avSync*` / `settingAvSync*` / `avSyncMode*` 共 20 个键。

## 附录 B：与「反向报告」的差异

1. **F6 常量名有误**：绑定标记是 `custom-avs` + `av-names`，非 `custom-av-names`（N5）。
2. **附录 B 结论需限定条件**：「`itemID` 由内核自行分配」只在调用方**不传** `itemID` 时成立；`addAttributeViewBlocks` 接受调用方自带 `itemID`（N6）。因此「反向报告」§4.1 的错写隐患可以**根治**而非仅仅规避。
3. **§8 的覆盖风险可消除**：该风险源于「全表镜像」实现方式；改为事件驱动定向翻译后不存在陈旧快照（§3）。
4. **§9 Phase 3 的「双向同步」不再是高成本项**：因为 AV op 自带新值（N2），双向与单向共用同一套索引、编解码与幂等逻辑，边际成本主要是回声令牌与 AV 侧串行化。
